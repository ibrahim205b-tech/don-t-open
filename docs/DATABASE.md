# قاعدة البيانات

SQLite بوضع WAL، مع `foreign_keys=ON`. المخطط في `src/db/migrations/001_init.sql`، ويُطبَّق كل ملف ترحيل جديد (`NNN_name.sql`) تلقائياً عند الإقلاع داخل معاملة ويُسجَّل في `schema_migrations`. لا تعدّل ملف ترحيل طُبّق؛ أضف ملفاً جديداً.

## الجداول

| الجدول | الغرض |
| --- | --- |
| `users` | الحسابات. `role` من ٥ قيم (الزائر بلا حساب)، `status` فعّال/معطّل/محذوف، قفل المحاولات، سر TOTP |
| `sessions` | الجلسات؛ المعرّف هو SHA-256 للرمز، و`mfa_passed` للدخول بخطوتين |
| `areas`، `categories` | المناطق والتصنيفات لكل قسم (`is_food` للمطاعم) |
| `posts` | كل المحتوى العام بنوع (`business`، `job`، ...) وحالة، و`details` (JSON) للحقول الخاصة بكل نوع. `owner_id` لمالك النشاط المعتمد |
| `post_transitions` | الانتقالات المسموحة بين الحالات |
| `post_images`، `post_items` | الصور (أسماء عشوائية) والأصناف والأسعار |
| `post_revisions` | لقطة قبل كل تعديل |
| `moderation_actions` | كل تغيير حالة: من، متى، من أي حالة إلى أي حالة، السبب |
| `business_claims` | طلبات ملكية الأنشطة |
| `reviews` | تقييم واحد لكل مستخدم لكل منشور، بحالة مراجعة |
| `reports` | البلاغات على منشور أو تقييم |
| `featured_listings` | الترويج بتاريخ بداية ونهاية وموضع |
| `site_settings` | إعدادات قابلة للتعديل من قائمة مفاتيح محددة |
| `notifications` | إشعارات داخل الموقع |
| `audit_logs` | سجل تدقيق للإضافة فقط |
| `search_index` | FTS5: المنشورات المنشورة فقط بنص مطبّع |

> ملاحظة: المواصفات اقترحت جداول `roles` و`permissions` و`user_roles` منفصلة. اخترنا عموداً واحداً `users.role` مع قيد CHECK ومصفوفة صلاحيات في الكود (`src/auth/rbac.ts`) لأن الأدوار ثابتة وكل مستخدم له دور واحد؛ هذا أبسط وأقل عرضة للأخطاء، ويبقى المصدر الوحيد للصلاحيات هو الخادم.

## الضمانات داخل قاعدة البيانات

- `posts_insert_status`: المنشور الجديد يبدأ مسودة أو بانتظار المراجعة فقط.
- `posts_transition_guard`: يرفض أي انتقال حالة غير موجود في `post_transitions`.
- `posts_publish_guard`: النشر يتطلب `approved_by` لموظف فعّال، وليس صاحب المنشور (إلا المدير لما يضيفه بنفسه).
- `posts_back_to_review`: العودة للمراجعة تمسح الموافقة السابقة.
- `posts_verify_guard`: التوثيق ووسم «خبر مؤكد» لموظف فقط.
- `reviews_not_own`: لا تقييم لمنشورك ولا لمنشور غير منشور.
- `audit_logs_no_update`، `audit_logs_no_delete`: السجل لا يُعدَّل ولا يُحذف.
- قيود CHECK على الأطوال والقيم وأرقام الهواتف وصلاحية JSON.

## الفهارس

على النوع والحالة وتاريخ النشر (القوائم العامة)، المستخدم، المالك، طابور المراجعة، التصنيف، المنطقة، الانتهاء، كشف التكرار، والجلسات والإشعارات والسجل.
